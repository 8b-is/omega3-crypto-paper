# Ω₃ in plain language: three ways to stop lying

*An engineering walkthrough of the balanced-ternary, exact-dyadic, capability-sealed stack.*

There's a specific kind of dishonesty that creeps into distributed systems when
you're not looking:

1. **The precision lie** — "the value is 0.1" when it's really
   `0.1000000000000000055511151231257827`, and two machines disagree about which.
2. **The authority lie** — "the process has the file open" when the real question
   is "who said it was allowed to?"
3. **The integrity lie** — "it hasn't changed" when nobody actually checked.

Ω₃ attacks all three. Not with cleverness, but by making each lie *impossible to
type*.

---

## Lie 1: precision — exact dyadic rationals

Floating point can't represent `1/10`. That's fine until two replicas do the same
addition in different orders and land on different bits. Then your CRDT "merges"
into a state nobody has.

The fix is boring and total: **never leave the dyadic rationals**. Every number
is `m / 2^k` for integers `m, k`. With a fixed scale (`k = 16`), a value is a
single `i64`. Add and subtract are integer add/sub. The merge is `max`.

```rust
#[repr(transparent)]
pub struct Dyadic64(pub i64); // q = mantissa / 2^16
```

Why it works: `ℤ[1/2]` is closed under `+`, `−`, and `max` at a common scale.
There is no rounding step, so there's no place for order to matter. Two replicas
applying the same deltas in any order reach **identical bits**. Not "close
enough" — identical.

The same discipline applies to compression ratios: instead of `1.1348...`,
store `RationalPQ { p: 3761, q: 3314 }`, reduced by gcd. Exact forever.

## Lie 2: authority — capabilities, not names

Knowing the *name* of a resource shouldn't let you touch it. So in Ω₃ you don't
get names. You get an opaque handle:

```
VirtualCapHandle64 = (epoch_gen, cap_slot_id, futhark_tag_r2, block_offset)
```

The guest never sees a pointer or a syscall number. It says
`Op::Cap(handle, op, args)` and the host runs seven checks:

| # | Check | Why |
|---|-------|-----|
| 1 | 64-byte aligned | no torn cache lines |
| 2 | `CAP_ROOT_SEAL` not exported | the root capability can never leak |
| 3 | ternary polarity `{-1:guard, 0:RO, +1:RW}` | access rule is explicit |
| 4 | epoch match | no use-after-free across hot-swap |
| 5 | `3³ = 27` Futhark tag | domain isolation |
| 6 | carry-safe bounds | no overflow into the next slice |
| 7 | `req ⊆ allowed` | attenuation only, never elevation |

The beautiful part: the *same compiled guest* runs on POSIX `mmap`, in a WASM
linear memory, and on bare-metal DMA. The only thing that changes is the backend
behind the capability table — the logic is byte-identical.

## Lie 3: integrity — pack it, fold it, seal it

Ternary weights `{-1, 0, +1}` are the compact carrier. Map each trit to `t+1 ∈
{0,1,2}` and pack five per byte in `base-243`:

```
B = u₀·1 + u₁·3 + u₂·9 + u₃·27 + u₄·81   ∈ [0, 242]
```

`3^5 = 243 ≤ 256`, so it always fits, at `1.585 bits/trit` — `8×` denser than
FP16 for the same weights.

Then you seal. A 64-bit XOR fold is split into two **disjoint** bitplanes by a
`qt` mask (so `pos & neg == 0` — provably no leakage), and the whole 64-byte
`LitanyWireFrame` gets a 16-bit XOR tail over its first 62 bytes. The canonical
seal at `qt:55`, gate `0x62` is `0xe1034e575c371ab0`, and the same value is
produced by the Rust, Zig, and Go implementations. If they ever disagree, CI
screams.

## The reconciliation trick: Cartan torsion

Here's the one piece of real math. When two branches run concurrently, they don't
commute. Model the history as an oriented cell complex: states are 0-cells, steps
are 1-cells, and the concurrent branch is a 2-cell. The **torsion**

```
T(σ) = ∮_{∂σ} θ
```

is exactly the gap between "apply A then B" and "apply B then A" — a *translational
dislocation* in the state space. The semilattice join `⊔` is the retraction that
closes it: after the join, discrete Stokes' theorem holds exactly,
`∮ θ = 0`. Because the arithmetic is dyadic, that closure is bit-exact. Your
merge isn't approximate — it's a proof.

---

## What this is not

This is not cryptanalysis. It doesn't break anyone's cipher, and it doesn't try.
The "security" here is **structural honesty**: exact numbers, attenuated
authority, witnessed integrity. That's a narrower claim than "unbreakable" — and
it's a true one.
